# Art notes

Everything visual in this game is either CSS or inline SVG generated by
TypeScript. There are **no image files** other than `logo.svg`, and there are no
network requests of any kind at runtime — the artifact must work offline and
from any subpath.

## Where the art lives

| | |
|---|---|
| `content/logo.svg` | The route authority seal. Used by the repository's landing page and as the favicon. The only standalone asset. |
| `src/ui/icons.ts` | The UI icon set — `icon(name, size?, extraClass?)` returns SVG markup as a string. |
| `src/ui/art.ts` | The set pieces — `eraEmblem(1..5)`, `shipGlyph(classId)`, `endingPlate()`. |
| `src/styles.css` | The palette, on `:root`. Every colour in the game resolves from there. |

## The icon grid

- **24×24 viewBox**, always. Render size is passed in and defaults to 16.
- **1.6 stroke weight**, `round` caps and joins.
- `fill="none"`, `stroke="currentColor"`. **Icons never name a colour.** They
  inherit from the element they sit in, which is what lets the same glyph appear
  in an amber button and a dim table cell without a second copy.
- `aria-hidden="true"` and `focusable="false"` on every one. They are always
  beside a real text label, so they are decorative by construction. Never add a
  `<title>`.
- Keep each glyph to a handful of primitives. These render at 14–18px, where
  anything under about 1.5 units of the grid disappears entirely.

The set is a **system, not thirty drawings**. Before adding one, look at the
three nearest existing icons and match their optical weight — a new icon with
more nodes than its neighbours reads as bolder even at identical stroke width.

## Adding an icon

1. Add the name to the `IconName` union in `src/ui/icons.ts`.
2. Add its inner markup to the `PATHS` table. Inner markup only — `icon()`
   supplies the `<svg>` wrapper, so do not include one.
3. Check it at 14px, not at 100px. If it only works large, it is too detailed.

TypeScript will tell you if you add a name without a path, or a path without a
name, because `PATHS` is typed as `Record<IconName, string>`.

## The set pieces in `art.ts`

`eraEmblem` returns five circular seals, each a technical diagram of that era's
binding constraint — a Hohmann transfer, a light cone, a warp bubble, receding
galaxies, branching manifolds. These are the game's five milestone images and
carry the most weight; they are drawn as certification stamps rather than
illustrations, which is the register the whole game is written in.

`shipGlyph` returns eleven orthographic side elevations. They must be
distinguishable at 40px, which means the silhouette does the work, not the
detail. Unknown ids return a neutral fallback rather than throwing.

Only these set pieces may name their own colours, and when they do it must be
through `var(--token, #literalfallback)` so a renamed variable degrades to a
sensible colour instead of to black.

## House rules

- No `<image>`, no base64, no external references, no `<style>` blocks inside
  SVG, no scripts.
- No glow, no scanlines, no lens flare. The aesthetic is an operations console
  at a port authority, not a spaceship cockpit.
- Nothing may convey information by colour alone. Where a glyph encodes state,
  the surrounding markup carries the word too.
